## Grid Basics

**CSS Grid** arranges elements in rows and columns. It keeps columns aligned across rows, which is useful for cards, forms, and page layouts.

### Create a grid container

```html
<!-- [!code word:class="grid"] -->
<div class="grid">
  <article>Revenue</article>
  <article>Orders</article>
  <article>Customers</article>
  <article>Support</article>
</div>
```

```css
/* [!code word:display\: grid] */
/* [!code word:grid-template-columns] */
/* [!code word:grid-template-rows] */
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
  grid-template-rows: auto auto;
  gap: 1rem;
}
```

The wrapper becomes the **grid container**. Its direct children in normal flow become **grid items**. The browser places these four articles into two columns and two rows in source order. The `fr` unit shares available space; later lessons examine track sizing in detail.

A paragraph nested inside an article is not another item in the outer grid. It stays inside that article's own layout.

| Term | Meaning in this example |
| --- | --- |
| Grid line | A boundary between tracks or at an outer edge. |
| Track | The space between two neighboring lines: one row or column. |
| Cell | The intersection of one row track and one column track. |
| Area | A rectangular region containing one or more cells. |
| Gap | The gutter between neighboring tracks. |

Two columns have three column lines. Two rows have three row lines. The four intersections form four cells, but an item can also span several cells to occupy a larger area.

Lines are numbered from 1. In horizontal, left-to-right text, column line 1 is at the left and row line 1 is at the top. Column numbering starts from the right for right-to-left text.

### Separate tracks with gaps

```css
/* [!code word:1rem 2rem] */
.grid {
  gap: 1rem 2rem;
}
```

Add this rule after the earlier grid rule. With two gap values, the first sets row gaps and the second sets column gaps. With one value, both use that value.

- Gaps separate tracks without adding outer padding.
- A gap is not an extra cell that receives an item.
- Gaps take space before flexible tracks share what remains.

For example, in a 640-pixel content width with a 16-pixel root font size, the 32-pixel column gap leaves 608 pixels for two unconstrained equal tracks: 304 pixels each.

### Separate the grid from its content

The grid defines spaces, not new HTML elements. Cells can stay empty, and an item can cover several cells. Set up the rows and columns on the container, then let the browser place items or choose their positions yourself.

## Grid Tracks

The rows and columns you define with template properties make up the **explicit grid**. Each track can have a fixed size, fit its content, or share available space.

### Define columns and rows

```css
/* [!code word:12rem 1fr] */
/* [!code word:4rem auto 3rem] */
.page {
  display: grid;
  grid-template-columns: 12rem 1fr;
  grid-template-rows: 4rem auto 3rem;
  gap: 1rem;
}
```

Each space-separated size defines one track:

- **Columns:** A `12rem` column followed by a flexible `1fr` column.
- **Rows:** A `4rem` row, an automatic row, and a `3rem` row.
- **Gap:** Space between neighboring tracks on each axis.

This defines two columns and three rows. It does not automatically make an item span both columns; placement is a separate decision.

With an 800-pixel content width and a 16-pixel root font size, the first column uses 192 pixels and the gap uses 16. The flexible column receives the remaining 592 pixels when content minimums do not force it wider.


### Choose a sizing approach

| Track value | Behavior |
| --- | --- |
| `12rem` | A fixed length relative to the root font size. |
| `auto` | Uses automatic sizing that considers the items' content and available space. |
| `1fr` | Receives a share of leftover space, subject to its minimum. |

Fixed row heights can be useful for a deliberate size, but text can outgrow them. The `auto` middle row can respond to its content. If a container has extra height, automatic rows can also stretch under the default content alignment.

`fr` rows share space in the grid, not the viewport. Give the container a set height when you want rows to divide a known amount of vertical space.

### Repeat a track pattern

```css
/* [!code word:repeat(3, 1fr)] */
.three-columns {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1rem;
}
```

`repeat(3, 1fr)` writes `1fr 1fr 1fr` compactly. The count repeats the supplied track pattern; it does not limit the total number of items to three.

If six short articles use this grid, automatic placement fills two rows while preserving the same three column boundaries. Rows not explicitly listed are created as needed; the Implicit Grids lesson covers their sizing.

### Keep percentage tracks and gaps in mind

Two `50%` columns already consume the container's full width. Adding a nonzero gap can make the tracks overflow because the percentages do not automatically subtract the gap.

Use `fr` to divide the space left after gaps. A plain `1fr` track still has a content-based minimum, so long text can make it wider. The next lesson uses `minmax()` to control that limit.

### Key Takeaways

- **Explicit tracks:** Template properties define the grid's intended rows and columns.
- **Mixed sizes:** Fixed, automatic, and fractional tracks can coexist.
- **Repetition:** `repeat()` abbreviates a track pattern, not an item limit.
- **Available space:** Account for gaps, content minimums, and the container's dimensions.

## Flexible Grids

A flexible grid adjusts its column widths and column count to the available space. Use `fr` to share space, `minmax()` to set limits, and `repeat()` to create columns.

### Share leftover space with `fr`

```css
/* [!code word:minmax(0, 1fr)] */
/* [!code word:minmax(0, 2fr)] */
.ratio {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(0, 2fr);
  gap: 1rem;
}
```

At a 616-pixel content width with a 16-pixel gap, 600 pixels remain for the tracks. They receive 200 and 400 pixels: one share and two shares.

`minmax(0, 1fr)` sets a zero track minimum instead of the automatic minimum of a bare `1fr`. This allows the track to shrink, but the content inside it still needs to wrap or handle overflow.

### Repeat equal tracks

```css
/* [!code word:repeat(3, minmax(0, 1fr))] */
.equal {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1rem;
}
```

This always defines three columns. They become narrower together as the container narrows; repetition with a numeric count does not change that count.

`minmax()` takes a minimum followed by a maximum. A flexible `fr` value is valid in the maximum position, but not the minimum position.

### Let the number of columns adapt

```css
/* [!code word:auto-fit] */
/* [!code word:minmax(14rem, 1fr)] */
.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(14rem, 1fr));
  gap: 1rem;
}

.catalog > article {
  min-width: 0;
  overflow-wrap: anywhere;
}
```

The browser creates as many `14rem` minimum columns as fit, accounting for gaps, then distributes extra width through the `1fr` maximum. Empty repeated tracks collapse with `auto-fit`.

With a 16-pixel root font size and enough items:

| Container width | Columns that fit |
| --- | --- |
| 1000px | Four: the minimum widths plus three gaps take 944px. |
| 700px | Two: three columns and their gaps would take 704px. |
| 300px | One. |

The count depends on container space, not the number of items on just the final row.

### Compare `auto-fit` and `auto-fill`

```css
/* [!code word:auto-fill] */
.reserved {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(14rem, 1fr));
  gap: 1rem;
}
```

Both initially create tracks that fit. The difference appears when whole repeated tracks are empty:

- **`auto-fill`:** Keeps those empty tracks, reserving space for them.
- **`auto-fit`:** Collapses them so occupied flexible tracks can expand.

`auto-fit` collapses a column only if the whole column is empty. An empty cell in the last row is not enough.

### Allow a smaller container

A strict `14rem` minimum overflows a container narrower than that value. To allow one track to become as narrow as its container, replace the catalog's template with:

```css
/* [!code word:min(100%, 14rem)] */
.catalog {
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
}
```

The `min()` function lowers the minimum when the container is narrower than `14rem`. Keep the content wrapping rules as well.

### Key Takeaways

- **`fr`:** Shares leftover track space after gaps.
- **`minmax()`:** Sets track limits; `fr` belongs in the maximum position.
- **Automatic repetition:** Changes the number of columns that fit.
- **Empty tracks:** `auto-fit` collapses them; `auto-fill` retains them.

## Implicit Grids

Grid can add rows or columns when more items need space. These are **implicit tracks**, and they let your layout grow without a set row count.

### Let automatic placement add rows

```html
<!-- [!code word:class="list"] -->
<div class="list">
  <article>Overview</article>
  <article>Analytics</article>
  <article>Projects</article>
  <article>Reports</article>
  <article>Settings</article>
</div>
```

```css
/* [!code word:grid-template-rows] */
/* [!code word:grid-auto-rows] */
/* [!code word:minmax(6rem, auto)] */
.list {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  grid-template-rows: 4rem;
  grid-auto-rows: minmax(6rem, auto);
  gap: 1rem;
}
```

For these items, default row-wise placement fills two cells in the first row, two in the next, then one in a third row.

- The first row is explicit and uses `4rem`.
- The second and third rows are implicit and use `minmax(6rem, auto)`.
- Additional items can create more implicit rows.

`grid-auto-rows` sizes automatically created rows; it does not replace the explicit row template. An `auto` maximum lets these implicit rows grow when their content needs more than the minimum.

### Understand the placement direction

The initial `grid-auto-flow` value is `row`. It fills rows in turn and creates more rows as needed. For ordinary items without placement or `order` overrides, the sequence follows source order.

You can instead fill columns:

```css
/* [!code word:column] */
/* [!code word:grid-auto-columns] */
.columns {
  display: grid;
  grid-template-rows: repeat(2, 5rem);
  grid-auto-flow: column;
  grid-auto-columns: 10rem;
  gap: 1rem;
}
```

Two items occupy the first column before placement advances to the next. `grid-auto-columns` gives the implicit columns a `10rem` size. A long collection can therefore become wider than its container; column flow is not automatic horizontal scrolling.

### Recognize gaps left by spans

If a later item needs two columns but only one cell remains on the current row, default placement moves forward until it finds enough room. A smaller item appearing after it may leave the earlier hole unfilled.

```css
/* [!code word:row dense] */
.packed {
  grid-auto-flow: row dense;
}
```

`dense` lets the browser fill earlier gaps with later items that fit. This can change their visual order while leaving the HTML and usual Tab order unchanged. Check that the result still makes sense.

### Inspect unexpected implicit tracks

An item placed beyond the rows or columns you defined can create implicit tracks too. When extra columns appear unexpectedly, inspect item line numbers and spans as well as the template.

Use a grid overlay to distinguish explicit boundaries from added tracks.

### Key Takeaways

- **Implicit tracks:** Appear when placement needs tracks beyond the explicit grid.
- **Automatic sizing:** `grid-auto-rows` and `grid-auto-columns` size those added tracks.
- **Flow:** Row flow adds rows; column flow adds columns.
- **Dense packing:** Can fill earlier holes while changing visual order.
