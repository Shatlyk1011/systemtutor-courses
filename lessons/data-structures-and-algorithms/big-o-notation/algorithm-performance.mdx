An **algorithm** is a sequence of steps that solves a problem. Suppose you need the smallest reading in a nonempty list of sensor measurements. Before comparing solutions, agree on what they must return.

## Compare two correct solutions

For `[5, 2, 8, 1, 9]`, both of these methods return `1`:

- **Sort a copy.** Make a new list, sort it from smallest to largest, and read the first value.
- **Scan once.** Remember the first value, then compare each remaining reading with the smallest seen so far. The remembered value goes from `5` to `2`, stays at `2` after seeing `8`, drops to `1`, then stays there after `9`.

![Two algorithms find the same minimum value, 1, using different amounts of work, time, and memory.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/18ada0b2-6e63-4158-a51d-f5d75673751a/gallery/23c2a89d-0266-4df7-bfb5-9d6a43928c24)

For five readings, the scan needs four comparisons and one variable for the current minimum. For a million readings, it needs 999,999 comparisons and the same variable. Sorting the copy also puts every other value in order, and it reserves memory for another list. If the only question is “which is smallest?”, the scan already does all the work you need.

## Key Takeaways

- **Time complexity** describes how the amount of work grows with the input size. Count the comparisons a scan makes before trying to predict elapsed seconds.
- **Space complexity** describes how memory use grows. A remembered minimum stays small even as a copied list grows.
- Start with the output the problem requires. A sorted list is useful when later operations also need the full ordering.
