## Solution

Keep a search range that is guaranteed to contain the first bad version. If the middle version is bad, it may be the answer, so keep it and discard only later versions. If it is good, discard it and everything earlier.

![Checking versions 4, 6 and 5 narrows the inclusive range to version 5, the first bad version.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/ba5422b9-c8ef-4672-b067-9c87b70f4f60/gallery/900be525-8484-4bc9-b26c-07e9a8ebde2b)

The boundaries meet at the first version for which the bad-version condition is true.

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function firstBadVersion(n, firstBad) {
      let left = 1;
      let right = n;
    
      while (left < right) {
        const middle = left + Math.floor((right - left) / 2);
    
        if (middle >= firstBad) right = middle;
        else left = middle + 1;
      }
    
      return left;
    }
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def first_bad_version(n, first_bad):
        left = 1
        right = n
    
        while left < right:
            middle = left + (right - left) // 2
    
            if middle >= first_bad:
                right = middle
            else:
                left = middle + 1
    
        return left
    ```
  </Tab>
</Tabs>

### Big O notation

| Measure | Complexity | Explanation |
|---|---:|---|
| Time | `O(log n)` | Each version check halves the remaining range. |
| Auxiliary space | `O(1)` | The search uses only boundary and middle integers. |
