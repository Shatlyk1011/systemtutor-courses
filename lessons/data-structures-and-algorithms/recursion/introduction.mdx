A **recursive function** solves a problem by calling itself on a smaller subproblem. In a countdown from three, the call for `3` prints its number and asks the call for `2` to handle everything that follows. The call for `0` can finish immediately.

![Countdown calls itself with 3, 2, and 1 before reaching the base case at 0.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/f1b74d84-5ada-403c-b17f-1007370229f3/gallery/d67ad3b7-2529-4cb2-bd6e-e9d02b302ba8)

## Where recursion is used

A folder can contain files and other folders. To count its files, add the files directly inside it and ask the same counting function to handle each subfolder. The code follows the shape of the data even when the nesting depth is unknown. This example assumes a finite folder tree. When following links that can lead back to a previously visited node, track visited nodes to avoid circling forever.

## The Two Essential Ingredients

1. **Base case.** State which input you can answer directly.
2. **Progress.** Identify what moves closer to the base case on every recursive path. A countdown reduces the number. Traversing a finite tree moves down to a child.

![A recursive function returns at the base case or calls itself again with a smaller input.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/f1b74d84-5ada-403c-b17f-1007370229f3/gallery/f2b52631-afdb-4d81-8d9e-7853aa503949)

For a countdown starting at `3`, subtracting one each time reaches zero. Subtracting two each time skips zero. If your stopping test is exactly `n == 0`, that small change breaks the function for odd inputs.

## The Call Stack

The **call stack** records unfinished calls. Each call has its own frame, with its parameters, local variables, and the point where execution will resume. At the deepest point of `countdown(3)`, the calls for 3, 2, and 1 wait while the call for 0 runs.

![Each nested call places another frame on top of the call stack while earlier calls wait below it.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/f1b74d84-5ada-403c-b17f-1007370229f3/gallery/2b39b5d8-d0e7-4757-9720-24dcd51c1432)

When the call for 0 returns, the call for 1 resumes immediately after its recursive call. With no further work, it returns to 2, which returns to 3. Returning from a base case finishes **one** call. Its callers may still have work to do.

## Recursive Pattern: Countdown

Let's examine the simplest example of recursion: a function that counts down from a number $n$ to $1$, and then stops.

A recursive countdown function implements both required parts:

1. **Base case:** Stop when $n \le 0$.
2. **Progress:** Send $n - 1$ to the next call.

```text
countdown(n):
  if n <= 0:
    return

  print n
  countdown(n - 1)
```

The input becomes smaller on every call. When it reaches `0`, that call finishes and control returns through the waiting calls.

### Implementation

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function countdown(n) {
      // 1. Base Case: stops recursion
      if (n <= 0) {
        console.log("Blast off!");
        return;
      }

      // 2. Work: print current value
      console.log(n);

      // 3. Progress: call self with smaller input
      countdown(n - 1);
    }

    countdown(3);
    // Output:
    // 3
    // 2
    // 1
    // Blast off!
    ```
  </Tab>
  <Tab value="Python">
    ```python

            return

        # 2. Work: print current value
        print(n)

        countdown(n - 1)


    countdown(3)
    # Output:
    # 3
    # 2
    # 1
    # Blast off!
    ```

## Classic Recursion Examples

### 1. Sum of a Range (`sumRange`)

For a positive integer $n$, suppose we want to calculate the sum of all consecutive integers from $1$ up to $n$. For example:
- `sumRange(3)` $\rightarrow 3 + 2 + 1 = 6$
- `sumRange(4)` $\rightarrow 4 + 3 + 2 + 1 = 10$

Notice the recursive subproblem: $\text{sumRange}(n) = n + \text{sumRange}(n - 1)$. The smallest known answer is $\text{sumRange}(1) = 1$, which serves as our base case.

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function sumRange(n) {
      // Base case
      if (n === 1) return 1;

      // Recursive call with smaller input
      return n + sumRange(n - 1);
    }

    console.log(sumRange(3)); // 6
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def sum_range(n):
        # Base case
        if n == 1:
            return 1

        # Recursive call with smaller input
        return n + sum_range(n - 1)


    print(sum_range(3))  # 6
    ```
  </Tab>
</Tabs>

The additions happen on the way back. The call for `1` returns `1`. The waiting call for `2` returns `2 + 1 = 3`, and the call for `3` returns `3 + 3 = 6`.

### 2. Factorial (`factorial`)

The factorial of a non-negative integer $n$ (written as $n!$) is the product of all positive integers less than or equal to $n$:

$$4! = 4 \times 3 \times 2 \times 1 = 24$$

By definition, $0! = 1$ and $1! = 1$. The recursive relationship is:

$$n! = n \times (n - 1)!$$

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function factorial(n) {
      // Base case: 0! and 1! both equal 1
      if (n <= 1) return 1;

      // Recursive step: n * factorial(n - 1)
      return n * factorial(n - 1);
    }

    console.log(factorial(4)); // 24
    console.log(factorial(5)); // 120
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def factorial(n):
        # Base case: 0! and 1! both equal 1
        if n <= 1:
            return 1

        # Recursive step: n * factorial(n - 1)
        return n * factorial(n - 1)


    print(factorial(4))  # 24
    print(factorial(5))  # 120
    ```
  </Tab>
</Tabs>

### 3. Traversing Nested Data (Real-World Example)

Imagine you receive an array of numbers that contains other nested arrays at unpredictable depths:

```js
const numbers = [1, [2, [3, 4], 5], 6];
```

Calculating the total sum with regular loops is cumbersome because the nesting depth is unknown. With recursion, each element is either a number (base case) or another array to recurse through:

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function sumNested(items) {
      let total = 0;

      for (const item of items) {
        if (Array.isArray(item)) {
          // Recursive step: process the nested array
          total += sumNested(item);
        } else {
          // Base item: directly add the number
          total += item;
        }
      }

      return total;
    }

    console.log(sumNested([1, [2, [3, 4], 5], 6])); // 21
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def sum_nested(items):
        total = 0

        for item in items:
            if isinstance(item, list):
                # Recursive step: process the nested list
                total += sum_nested(item)
            else:
                # Base item: directly add the number
                total += item

        return total


    print(sum_nested([1, [2, [3, 4], 5], 6]))  # 21
    ```
  </Tab>
</Tabs>

## Collecting Results Recursively

To collect odd values from an array, recursion can process the array while leaving the original unchanged. Two common approaches are **helper method recursion** and **pure recursion**.

### Helper method recursion

An outer function defines the accumulator array, while an inner recursive helper function populates it as it processes the input:

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function collectOddValues(arr) {
      const results = [];

      function helper(index) {
        // Base case: all elements processed
        if (index === arr.length) {
          return;
        }

        // Work: collect odd number
        if (arr[index] % 2 !== 0) {
          results.push(arr[index]);
        }

        // Progress: recurse with remaining elements
        helper(index + 1);
      }

      helper(0);
      return results;
    }

    console.log(collectOddValues([1, 2, 3, 4, 5])); // [1, 3, 5]
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def collect_odd_values(arr):
        results = []

        def helper(index):
            # Base case: all elements processed
            if index == len(arr):
                return

            # Work: collect odd number
            if arr[index] % 2 != 0:
                results.append(arr[index])

            # Progress: recurse with remaining elements
            helper(index + 1)

        helper(0)
        return results


    print(collect_odd_values([1, 2, 3, 4, 5]))  # [1, 3, 5]
    ```
  </Tab>
</Tabs>

### Pure recursion

Pure recursion is completely self-contained—each recursive call creates and returns its own results, which are combined as the call stack unwinds:

<Tabs items={["JavaScript", "Python"]}>
  <Tab value="JavaScript">
    ```js
    function collectOddValues(arr) {
      let results = [];

      // Base case: empty array
      if (arr.length === 0) {
        return results;
      }

      // Work: collect odd number
      if (arr[0] % 2 !== 0) {
        results.push(arr[0]);
      }

      // Progress: combine with recursive call on remaining elements
      results = results.concat(collectOddValues(arr.slice(1)));

      return results;
    }

    console.log(collectOddValues([1, 2, 3, 4, 5])); // [1, 3, 5]
    ```
  </Tab>
  <Tab value="Python">
    ```python
    def collect_odd_values(arr):
        results = []

        # Base case: empty list
        if len(arr) == 0:
            return results

        # Work: collect odd number
        if arr[0] % 2 != 0:
            results.append(arr[0])

        # Progress: combine with recursive call on remaining elements
        return results + collect_odd_values(arr[1:])


    print(collect_odd_values([1, 2, 3, 4, 5]))  # [1, 3, 5]
    ```
  </Tab>
</Tabs>

### Comparison

| Approach | How results are collected |
|---|---|
| Helper method recursion | An outer accumulator is modified by an inner recursive helper function. |
| Pure recursion | Each call returns independent results that are concatenated as the stack unwinds. |

Both approaches preserve the input. The index-based helper visits each value once and takes linear time. In the second version, each slice copies a shorter suffix. The copied lengths add up to quadratic time, even before accounting for the result concatenations.

## Common Recursion Errors

Check **termination** and **return values** separately.

| Symptom | What to inspect | Example |
|---|---|---|
| Calls keep accumulating | Check whether every path reaches a base case. | `sumRange(n)` calling `sumRange(n)` repeats the same work. |
| The function finishes with a missing result | Check that callers return the result they computed. | Calling `factorial(n - 1)` without returning the product loses the answer. |
| Correct calls exceed the stack limit | Count how many frames must be active at once. | Counting down from a very large integer can overflow even with a reachable base case. |

## Recursion vs. Iteration

A countdown needs only one counter in a loop. The recursive version keeps one frame per number until it reaches zero. In general, **maximum active depth** determines the stack cost when each frame uses constant space.

| Example | Maximum active depth | Space used for control |
|---|---|---|
| Countdown from `n` | About `n` calls | `O(n)` recursive frames, or `O(1)` for a loop with one counter |
| Repeatedly halve a positive `n` | About `log₂ n` calls | `O(log n)` recursive frames |
| Traverse a nested folder tree | About the tree height | Recursive frames or an explicit collection of pending folders |

## Key Takeaways

- **Self-Calling Function:** Recursion occurs when a function calls itself to solve smaller subproblems of the same type.
- **The Two Non-Negotiables:** Every recursive function must have a **base case** to stop execution and a **progress step** that moves input closer to that base case.
- **Call stack cost:** Count the calls active at the same time. A reachable base case ensures termination when the input keeps making progress, but a deep chain can still exceed the stack limit.
