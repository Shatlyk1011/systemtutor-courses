## What is an Algorithm Pattern?

![Pattern selection guide](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/1e3e13b6-0db0-43d8-9eab-205bdcf6fa8f/gallery/7f1ef359-198c-4b63-9ef3-66dbae68bb80)

An **algorithm pattern** is a repeatable recipe or template for solving common coding problems.

Instead of guessing or starting from scratch on every problem, patterns give you a proven game plan. Most interview and LeetCode problems are just variations of a few core patterns.

<Callout title="Key Idea" type="info">
Don't memorize individual problems. Learn the **patterns** behind them so you can solve hundreds of problems with the same core technique.
</Callout>

---

## Why Use Patterns?

- **Faster Solutions:** Spot what a problem needs in seconds instead of getting stuck.
- **Better Performance:** Avoid slow nested loops ($O(n^2)$) and write fast, clean code ($O(n)$).
- **Clear Game Plan:** Know right away which data structure to pick and how to walk through the data.

---

## Quick Cheat Sheet

Here is how to spot the right pattern based on what the problem asks:

| If you see... | Try this pattern | Why it works |
| :--- | :--- | :--- |
| Comparing counts, anagrams, duplicates | **Frequency Counters** | Uses a hash map to count items in one pass |
| Sorted list, finding pairs, opposite ends | **Two Pointers** | Moves two pointers to avoid checking every pair |
| Contiguous sub-array, longest substring | **Sliding Window** | Expands and shrinks a window without re-scanning |
