**Before you begin** — [IP](/courses/system-design/docs/networking/ip).

A server delivering a file needs the receiver to see the original bytes in order. **TCP (Transmission Control Protocol)** gives applications a reliable, ordered byte stream while the connection remains usable. IP can take care of routing each packet even if different packets experience different delays.

## Establish a connection

Before a typical TCP connection carries application data, the endpoints synchronize their starting sequence numbers for the two directions of travel.

1. **SYN.** The client sends its initial sequence number.
2. **SYN-ACK.** The server acknowledges the client’s SYN and sends its own initial sequence number.
3. **ACK.** The client acknowledges the server’s SYN. This segment can also carry application bytes.

![The client sends SYN, the server replies SYN-ACK, and the client sends ACK.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/54de4736-cbfb-4ca3-add4-542a111f11df/gallery/46e9284c-2dc6-4c6c-ad4d-179a84d1dd49)

The client typically waits one round trip for the SYN-ACK before sending its first application bytes. Reusing an established connection avoids paying that setup cost for another request. [TCP specification, connection establishment](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.5)

## Recover a gap in the stream

TCP can divide a block of application bytes into **segments** that travel in IP packets. A segment’s sequence number identifies the position of its first data byte in the stream. Segment boundaries may differ from the boundaries between an application’s writes.

![TCP divides a block of application bytes into four segments for transmission.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/e25a97c7-7bb0-4a6e-a419-05a6f6f3c1fa/gallery/cc752618-d93c-4fcb-ac6c-ee38df3b78c9)

Imagine four data segments sent in order. The receiver gets the first, third, and fourth. It can deliver the bytes from the first segment to the application and buffer later bytes. It has to wait to deliver the bytes beyond the gap because the application reads one ordered stream.

![Segment 2 is missing when 3 and 4 arrive. The receiver can deliver the complete ordered sequence once 2 is retransmitted.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/54de4736-cbfb-4ca3-add4-542a111f11df/gallery/51ee2a4c-a8a1-4410-b75f-47f4bcd778d7)

The numbers 1 through 4 in the figure label pieces of data for illustration. On the wire, TCP counts bytes. A cumulative **acknowledgement (ACK)** tells the sender the next byte the receiver expects in order. When the sender detects loss, it retransmits the missing data. Once the gap is filled, the receiver can deliver the newly contiguous bytes. If the connection breaks before recovery completes, the application must handle failure.

## Decide when ordering pays for itself

For a file transfer, losing a piece would leave the file incomplete. TCP’s setup, acknowledgements, and retransmissions support the delivery behavior the application needs. For rapidly changing game positions, a newly arrived snapshot may already replace the missing one. Holding the fresh snapshot behind older bytes can use up its useful lifetime.

HTTP/1.1, HTTP/2, email protocols such as SMTP, and SSH commonly use TCP. HTTP/3 uses QUIC, a transport that supplies reliable streams over UDP.

## Key Takeaways

- **Connection setup** establishes sequence numbers in both directions and costs about one round trip for the initiating client.
- **Sequence numbers and ACKs** let TCP detect gaps and recover the ordered byte stream.
- **Ordered delivery** can make later bytes wait for earlier data. Consider that wait when a message has a deadline.
