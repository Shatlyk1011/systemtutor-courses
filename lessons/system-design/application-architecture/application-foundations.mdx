<Callout title="Lesson goal" type="info">
  Trace how a code change reaches production and how a profile request uses the running application.
</Callout>

A developer adds a display name to a profile page. Saving the change in source control records the new version. For a user to see it, that version must be running when their browser asks for the profile. These two events belong to different paths that meet at the application.

## Follow a change into production

The **delivery path** starts when the developer commits a change to source control. The build turns the source into something the runtime can execute, such as a package or container image. Tests check that the change behaves as expected.

![A developer commits code to source control. Build and test precede deployment to the runtime.](https://pub-d143c03df8bc45d5a4589bc793aa52e4.r2.dev/courses/ba63474e-1b92-4442-ad73-e67e7b1b8070/gallery/d5eb3c7f-c468-4a2f-8be2-e51ddcf0b879)

Deployment places the selected build into its target environment. The **runtime** executes it with the configuration, network access, and credentials it needs to serve requests. A profile request reaches the version currently serving traffic. A newer commit can still be waiting for deployment.

## Trace a profile request

The **request path** begins when a user opens their profile. The browser acts as the client. It calls the application's **API**, the interface through which the client asks for data or actions. The application can expose that interface directly or receive requests through a gateway.

![The browser requests a profile from the application. Only the application reads the database and returns the profile to the browser.](/course-images/system-design/application-architecture/application-foundations/application-foundations-profile-request.png)

1. The browser asks the application for the user's profile.
2. The application checks who is making the request and whether that person may view the profile.
3. The application reads the record from persistent storage. The database returns the profile data to the application.
4. The application forms a response. The browser receives it and displays the profile.

When the user edits their display name, the request follows the same route to the application. This time the application validates the change, writes the new value to storage, and confirms the update. Reading and writing have different effects on the stored record.

## Check your understanding

The profile change passed its build and tests. Users still see the old display, and profile reads succeed. Which path would you check first?

Start with delivery. Find out which build is serving users. A successful profile read confirms that a running version handled the request. The deployment record tells you whether it was the version with the new display.

</details>

## Key Takeaways

- The **delivery path** turns a source change into a running version.
- The **request path** carries a client action through application logic to data and back.
- The paths meet at the runtime. Checking the deployed version and tracing a request answer different diagnostic questions.
